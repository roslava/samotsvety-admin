# Samotsvety — Структура данных и API

## Общая архитектура данных

Данные организованы вокруг основной сущности — **GemEntity** (самоцвет / минерал / горная порода / разновидность).

> **Важное обновление:** Структура теперь поддерживает **горные породы**, разновидности и органику.

Структура поддерживает:

- Два языка (русский и английский)
- Два режима отображения (Обычный и С эзотерикой)
- Чёткое разделение научной, историко-культурной и эзотерической информации
- Поле `type` для классификации сущности

## Основные принципы

1. **Научные данные** — всегда точные, нейтральные и фактологические.
2. **Lore (история и культура)** — исторический, культурный и локальный контекст.
3. **Esoteric (эзотерика)** — метафизические свойства, энергетика, чакры, зодиак и т.д. Показываются только в соответствующем режиме.
4. **i18n** — все переводимые поля вынесены в отдельный блок.
5. **Гибкость** — некоторые научные поля являются опциональными в зависимости от `type`.

# Подробное описание полей

## Верхний уровень

| Поле | Тип | Описание | Обязательно |
|------|-----|----------|:-----------:|
| `slug` | `string` | Уникальный идентификатор | ✅ Да |
| `type` | `enum` | `mineral` / `rock` / `gem_variety` / `organic` | ✅ Да |

---

## Блок `scientific`

| Поле | Тип | Описание | Обязательно |
|------|-----|----------|:-----------:|
| `chemical_formula` | `string` | Химическая формула | Условно |
| `mineral_group` | `string` | Минеральная группа или тип породы | ✅ Да |
| `crystal_system` | `string` | Кристаллическая система | Условно |
| `crystal_habit` | `string` | Форма кристаллов и агрегатов | Нет |
| `hardness` | `object` | Твёрдость по шкале Мооса (`min`, `max`) | ✅ Да |
| `specific_gravity` | `object` | Удельный вес (`min`, `max`) | ✅ Да |
| `streak` | `string` | Цвет черты | ✅ Да |
| `luster` | `string` | Блеск | ✅ Да |
| `transparency` | `string` | Прозрачность | ✅ Да |
| `cleavage` | `string` | Спайность | Нет |
| `fracture` | `string` | Излом | Нет |
| `rarity` | `enum` | `common` / `uncommon` / `rare` / `very_rare` | ✅ Да |
| `ima_status` | `string` | Статус IMA | Нет |
| `identification_tips` | `string` | Советы по идентификации | Нет |
| `composition` | `string` | Преобладающий состав | Нет |
| `rock_type` | `string` | Тип горной породы | Нет |
| `phenomena` | `array` | Оптические эффекты | Нет |

---

## Блок `i18n`

Содержит переводимые поля для каждого языка (`ru` и `en`).

### Обязательные поля

| Поле | Описание |
|------|----------|
| `name` | Основное название |
| `lore` | Исторический и культурный контекст |

### Блок `esoteric`

> Показывается только в режиме **«С эзотерикой»**.

| Поле | Тип | Описание |
|------|-----|----------|
| `metaphysical_properties` | `array` | Метафизические свойства |
| `chakras` | `array` | Связанные чакры |
| `zodiac` | `array` | Знаки зодиака |
| `healing_interpretation` | `string` | Интерпретация в эзотерической традиции |
| `energy_notes` | `string` | Заметки об энергетике |
| `ritual_uses` | `string` | Ритуальное применение (опционально) |

---

## Блок `localities`

Массив объектов с информацией о месторождениях.

Особое внимание уделяется российским месторождениям через флаг:

- `is_russian`

---

## Медиа

### `main_image_url`

Главное изображение минерала.

### `gallery`

Массив изображений с указанием типа:

- `specimen`
- `polished`
- `jewelry`
- `micro`
- и другие

# Рекомендации по API

## Базовые REST-эндпоинты

| Метод | Endpoint | Описание |
|-------|----------|----------|
| `GET` | `/api/v1/minerals` | Список минералов (с фильтрами) |
| `GET` | `/api/v1/minerals/{slug}` | Полная карточка минерала |
| `GET` | `/api/v1/search` | Поиск по названию и свойствам |
| `GET` | `/api/v1/filters` | Доступные значения фильтров |

---

## Основные query-параметры

| Параметр | Описание |
|----------|----------|
| `lang=ru\|en` | Язык ответа (по умолчанию `ru`) |
| `view=normal\|esoteric` | Режим отображения |
| `rarity` | Фильтр по редкости |
| `hardness_min` | Минимальная твёрдость |
| `hardness_max` | Максимальная твёрдость |
| `color` | Цвет |
| `russian_only=true` | Только российские месторождения |
| `limit` | Количество записей |
| `page` | Номер страницы |
| `type` | Тип сущности |

---

## Режим отображения

### `?view=esoteric`

В ответ включается блок `esoteric` внутри выбранного языка.

### `?view=normal`

Блок `esoteric` полностью отсутствует.

# Индексация и поиск

Рекомендуется индексировать:

- Названия (`name_ru`, `name_en`, синонимы)
- Цвета
- Месторождения (особенно российские)
- Метафизические свойства (для эзотерического поиска)
- Ключевые слова из `lore`

---

# Будущие расширения структуры

- `treatments` — облагораживание
- `price_range` — ориентировочные цены на образцы
- `user_generated_content` — фотографии пользователей и отзывы
- `3d_model_url` или AR-данные
- `related_products` — ссылки на товары

---

# Итоговые рекомендации

- Используйте предложенную структуру как базовую — она уже учитывает двуязычность и два режима отображения.
- Научные данные должны оставаться максимально точными и нейтральными.
- Эзотерический блок рекомендуется формулировать мягко: «в эзотерической традиции считается...», «многие практики отмечают...» и т.п.
- Раздел **Lore** является универсальным и подходит для отображения в обоих режимах.
- API желательно сделать максимально гибким: сервер может возвращать полный набор данных, а фронтенд — самостоятельно решать, какие блоки отображать в зависимости от выбранного режима.

---

## Заключение

Предложенная структура позволяет масштабировать проект одновременно в двух направлениях:

- как научный каталог минералов и горных пород;
- как эзотерический справочник.

При этом обе аудитории могут использовать один и тот же API без конфликтов между научным и метафизическим представлением информации.
